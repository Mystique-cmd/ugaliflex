A lexical analyser ( scanner ) generated using JFLEX can be integrated with a syntax analyzer ( parser ) using CUP ( Constructor of Useful Parsers ). These two tools work together to form the frontend of a compiler. 
JFLEX is responsible for reading the source program character by character, grouping characters into meaningful tokens and passing those tokens to the parser. CUP receives the tokens checks whether they follow the grammatical rules of the programming language.

### Token Generation by JFLEX
JFLEX uses regular expressions and associated actions to identify lexical patterns in source code. A JFLEX specification typically contains three sections:
- User code and declarations
- Lexical rules and regular expressions
- Actions executed when patterns are matched.

When JFLEX encounters a matching character sequence, it executes the associated action and returns a token. JFLEX does not normally determine whether the sequence of tokens forms a valid statement.

###  Passing tokens from scanner to parser
Integration is achieved  through common token interface. CUP provides a scanner interface which defines next_token() method. The JFLEX generated scanner can implement this interface. The scanner returns tokens represented by CUP's symbol class.
A typical JFLEX configuration includes:
```jflex
%class Lexer
%implements java_cup.runtime.Scanner
%cup
```
The %cup directive configures the generated scanner for compatibility with CUP
The process works as follows:
- The parser requests the next token from the scanner
- JFLEX reads the input and identifies the next token
- JFLEX returns the token as a CUP symbol object
- CUP receives the token and compares it with the expected grammar symbols
- The parser requests another token when necessary
- This continues until parsing is completed or an error occurs.

### Token Attributes
The tokens may contain additional information besids their token types. These additional values are called token attributes.
CUP uses the symbol class to represent the tokes. A symbol contains information such as
- sym : the token type
- value : the actual attribute or semantic value
- left and right : optional source-position commonly used for line and column tracking

In CUP terminals can be declared with associated Java data types and then JFLEX can return tokens containing their actual values. The parser can access these attributes in grammat production actions.
The token attributes allow the parser to work with actual identifier names, numeric values and other information instead of merely knowing thata particular token exists.

### Role of the symbol table
A symbol table is a data structure maintained by the compiler to store information about identifiers used in a program. It acts as a central repository for information about variables, functions, contants and other declared entities.
Typical information stored includes:
- Identifier name
- Data type
- Scope
- Memory location and address
- Value
- Function parameters and return types

Here is how it works with JFLEX and CUP
- JFLEX identifies an identifier such as age
- It generates and identifier token carrying the name age
- CUP receives the token
- When parsing a declaration, CUP can use a grammar action to inster the identifier and its declared type into the symbol table
- When parsing subsequent statements, the compiler can check whether the identifiers have been declared and whether their usage is valid.

### Lexical Erros vs Syntax Errors
Lexical errors occuer when the scanner encounters characters or character sequences that do not match any valid lexical patterns in the language.
JFLEX can handle errors using a catch-all rule. A production scanner should also account for end of file and multiline input when reporting errors

Syntax errors occur when the tokens generated by the lexical analyzer do not follow the grammar rules of the programming language. CUP detects these errors during parsing using its grammar rules and error handling mechanisms

The integration  invlolves the following major steps:
- Write lexical rules in a JFLEX specification file ( .flex )
- Write grammar production in a CUP specification file ( .cup )
- Generate the lexical analyzer using JFLEX
- Generate the parser using CUP
- Configure the JFLEX scanner to return CUP- compatible symbol objects
- Pass the scanner instance to the CUP parser
- Execute the parser which requests tokens from the scanner
- Performs syntax analysis and subsequent semantic analysis
